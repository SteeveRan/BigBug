## US-gitmrr-007: Проверить целостность зеркала

### Story Header

| Поле | Значение |
|-------|-------|
| ID | US-gitmrr-007 |
| Название | Проверить целостность зеркала |
| Персона | operator |

### User Story Statement

**Как** operator,

**я хочу** сравнить HEAD-коммиты источника и цели, обнаруживая ручные изменения в цели,

**чтобы** доверять зеркалу как точной копии и вовремя замечать дрейф цели.

### Context & Background

Зеркало существует, чтобы ему доверяли. Integrity check — прямое сравнение HEAD (ADR-0008) с вердиктами MATCH / MISMATCH / ERROR. Операция читает внешнее состояние, но чувствительна — охраняется собственным правом. Поток: UC-gitmrr-008.

### Acceptance Criteria

#### AC-1: Вердикт — один из трёх

**Дано** зеркало с привязанным целевым проектом

**Когда** я запускаю integrity check

**Тогда** система записывает MATCH, MISMATCH или ERROR в журнал зеркала и соответственно обновляет его состояние

#### AC-2: MISMATCH виден и посчитан

**Дано** integrity check вернул MISMATCH

**Когда** я смотрю зеркало

**Тогда** зеркало показывает warning-состояние с увеличенным счётчиком расшедшихся коммитов

#### AC-3: Право проверяется

**Дано** пользователь без права integrity-check

**Когда** он предпринимает операцию

**Тогда** система отклоняет её с 403 — эндпоинт не открыт любому аутентифицированному

### Technical Notes

- Целевое право `mirrors:integrity_check` (засеяно; admin+operator). Текущий код его не проверяет — расхождение зафиксировано в edge cases (EC-gitmrr-018) и grill #139 (C3).
