## US-gitmrr-009: Обнаружить осиротевшие GitLab-проекты

### Story Header

| Поле | Значение |
|-------|-------|
| ID | US-gitmrr-009 |
| Название | Обнаружить осиротевшие GitLab-проекты |
| Персона | admin |

### User Story Statement

**Как** admin,

**я хочу** находить GitLab-проекты на управляемых целевых инстансах, на которые не ссылается ни одно зеркало,

**чтобы** замечать расхождение между записями платформы и реальностью в GitLab.

### Context & Background

Orphaned discovery — отчёт по требованию над целевыми GitLab-инстансами: проекты, чьи id не ссылается ни одно активное зеркало (ADR-0008). Discovery только сообщает; исправление — отдельная story, переданная #160 (US-gitmrr-010, moved). Поток: UC-gitmrr-009 (шаги 1–2).

### Acceptance Criteria

#### AC-1: Осиротевшие перечислены

**Дано** целевой GitLab-инстанс с проектами, на которые не ссылаются зеркала

**Когда** я запускаю discovery

**Тогда** каждый проект без ссылки перечислен с путём, web URL и временем обнаружения

#### AC-2: Право проверяется

**Дано** пользователь без права управления orphaned

**Когда** он предпринимает discovery

**Тогда** система отклоняет с 403

#### AC-3: «Нет провайдеров» — действенный стейт, не generic-сбой

**Дано** ни одного активного GitLab-провайдера не настроено

**Когда** я открываю orphaned-страницу или запускаю discovery

**Тогда** система показывает действенный empty state («настройте GitLab-провайдера») со ссылкой в настройки провайдеров — не generic-ошибку загрузки

#### AC-4: Один сбойный провайдер не валит скан

**Дано** два GitLab-провайдера, один недоступен

**Когда** я запускаю discovery

**Тогда** доступный провайдер всё равно просканирован и его результаты возвращены; сбойный перечислен отдельно

### Technical Notes
