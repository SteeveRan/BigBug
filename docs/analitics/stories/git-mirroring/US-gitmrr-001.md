## US-gitmrr-001: Импортировать группу источников из Git-провайдера

### Story Header

| Поле | Значение |
|-------|-------|
| ID | US-gitmrr-001 |
| Название | Импортировать группу источников из Git-провайдера |
| Персона | operator |

### User Story Statement

**Как** operator,

**я хочу** импортировать GitHub-группу (организацию) со всеми её репозиториями одним действием,

**чтобы** зарегистрировать весь источник целиком вместо ввода репозиториев по одному.

### Context & Background

Зеркалирование начинается с инвентаря источников. GitHub-организация может содержать десятки репозиториев; ручной ввод не масштабируется. Платформа должна разрешить группу через настроенный Resource Provider и зарегистрировать её репозитории как source repositories (поток: UC-gitmrr-001).

### Acceptance Criteria

#### AC-1: Импорт по идентификатору группы

**Дано** существует Git-провайдер с валидными credentials

**Когда** я отправляю импорт с указанием провайдера и идентификатора группы

**Тогда** система регистрирует группу и все репозитории, видимые этим credentials, и сообщает число зарегистрированных

#### AC-2: Состояние импорта видно

**Дано** импорт завершился успешно

**Когда** я открываю страницу Sources

**Тогда** импортированная группа и её репозитории присутствуют в списке

#### AC-3: Refresh перечитывает источник

**Дано** импортированная группа существует

**Когда** я запускаю refresh

**Тогда** система перечитывает список репозиториев у провайдера и отражает появившиеся и исчезнувшие репозитории

### Technical Notes

- Импорт требует `source_groups:write`; список/детали — `source_groups:read`; refresh — `source_groups:refresh`.
- Получение метаданных репозиториев идёт в фоне после регистрации; список не должен блокироваться на нём.

### Dependencies

| Зависимость | Тип | Статус |
|------------|------|--------|
| Resource Provider с GitHub credentials | Feature | Ready |

### Out of Scope

- Выбор подмножества репозиториев при импорте (импорт — всё-или-отчёт)
- Автоматический повторный импорт по расписанию
