# Architecture Decision Records — актуальные решения

Реестр **действующих** ADR проекта BigBug. Архив отменённых решений: [ARCHIVE.md](ARCHIVE.md).

## Конвенции

- **Каталоги компонентов**: `docs/adr/<component>/`, где component ∈ `common` | `backend` | `frontend` | `infrastructure`.
- **Сквозная нумерация**: `NNNN` едина для всех компонентов. Следующий номер = максимальный номер среди **всех** ADR (активные + `archive/`) + 1. Дубли номеров недопустимы.
- **Имя файла**: `NNNN-slug.md` (kebab-case, англоязычный slug), например `0007-providers-v3-registry.md`.
- **Формат**: MADR 4.0, шаблон [`_template.md`](_template.md). Свой шаблон не изобретать.
- **Язык ADR**: русский; технические термины не переводить (Providers, RBAC, pipeline, webhook).
- **Статусы**: `Proposed → Accepted` (решает человек) `→ Superseded` (заменён новым ADR) или `Rejected`.
- **Accepted ADR обязательны к исполнению**; Proposed — информационные, но учитывать.
- **Архивация**: при `Superseded`/`Rejected` файл перемещается в `docs/adr/archive/<component>/`, в front-matter заполняется `superseded_by`, строка удаляется из этого реестра и добавляется в `ARCHIVE.md`. Номер никогда не используется повторно.

## Правила для агентов

1. Перед любым архитектурным изменением / новой зависимостью / новым паттерном — прочитать этот реестр и релевантные Accepted ADR.
2. Новое решение, затрагивающее несколько компонентов, размещается в `common/`.
3. Создание ADR — через команду `/adr` (workflow skill `adr-skill`), а не вручную с нуля.
