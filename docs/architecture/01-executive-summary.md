# Executive Summary

## Цель проекта

BigBug - система для централизованного управления DevOps процессами, включающая:
- Управление Gold и App Docker образами
- Зеркалирование Git репозиториев (GitHub → GitLab)
- Синхронизация Docker образов и Helm чартов из внешних источников
- CI/CD пайплайны и GitLab Components
- Централизованное управление конфигурациями и доступами

## Масштабная переработка архитектуры

### Текущее состояние
- Базовая RBAC (3 роли: admin, operator, viewer)
- Аутентификация через Keycloak OIDC + локальные пользователи
- Интеграции с GitHub, GitLab (частично)
- Helm и Docker Registry синхронизация (базовая)
- Отсутствие управления интеграциями через UI
- Жёстко закодированные конфигурации интеграций

### Целевое состояние
- **Расширенная RBAC система** с кастомными ролями и глобальными permissions
- **Управляемые интеграции** - каждая интеграция настраивается через админ-панель
- **Множественные инстансы** - поддержка нескольких GitLab/Harbor/Registry
- **GitLab Pipelines** - создание и управление CI/CD через UI
- **GitLab Components** - создание переиспользуемых компонентов
- **Централизованное управление** всеми аспектами системы

## Ключевые архитектурные решения

### 1. RBAC и Permissions
- Переход от role-based к permission-based модели
- Глобальные permissions (не на уровне проектов)
- Возможность создания кастомных ролей
- Синхронизация ролей из Keycloak

### 2. Интеграции как First-Class Citizens
- Каждая интеграция - отдельная таблица БД
- Отдельные API endpoints для управления
- Dedicated сервисы для каждого типа интеграции
- Поддержка множественных инстансов одного типа

### 3. Аутентификация
- Локальная по умолчанию (email/password)
- OIDC опционально через настройки
- Слияние пользователей по email
- Инициализация с admin пользователем

### 4. Модульная архитектура сервисов
- Чёткое разделение ответственности
- Dependency Injection
- Изолированные интеграционные сервисы
- Переиспользуемые компоненты

### 5. UI/UX
- Административная панель только для Admin
- Настройка всех интеграций через UI
- Создание и редактирование пайплайнов в интерфейсе
- Role-based меню и компоненты

## Технологический стек

### Backend
- **FastAPI** - асинхронный REST API
- **SQLAlchemy 2.x** - ORM с async поддержкой
- **PostgreSQL 17** - основная БД
- **Redis 7** - кеширование и очереди
- **APScheduler** - планировщик задач
- **Cryptography** - шифрование credentials

### Frontend
- **React 19 + TypeScript**
- **Redux Toolkit + RTK Query**
- **Material UI v6**
- **React Router v7**

### Интеграции
- **python-gitlab** - GitLab API
- **PyGithub** - GitHub API
- **httpx** - Harbor, Docker Registry, Helm API
- **authlib** - OIDC/Keycloak

## Основные компоненты системы

### Builds Module
- Gold Images - базовые OS/runtime образы
- App Images - приложения поверх Gold образов
- Автоматические и ручные сборки
- Версионирование и tagging

### Mirroring Module
- Git Repositories (GitHub → GitLab)
- Docker Images (Registry → Harbor/Registry)
- Helm Charts (Repository → Harbor/ChartMuseum)
- Расписания синхронизации

### Pipelines Module (новое)
- My Pipelines - управление своими пайплайнами
- GitLab Components - переиспользуемые компоненты
- CI/CD конфигурации через UI
- Управление переменными и secrets

### Settings Module (расширенное)
- **Integrations** - настройка всех интеграций
- **Authentication** - Local + OIDC конфигурация
- **Users & Roles** - управление доступами

## Преимущества новой архитектуры

1. **Гибкость** - легко добавлять новые интеграции и функции
2. **Масштабируемость** - множественные инстансы сервисов
3. **Безопасность** - детальный контроль доступа, шифрование данных
4. **Управляемость** - всё настраивается через UI
5. **Расширяемость** - модульная структура позволяет легко расширять систему
6. **Переиспользование** - GitLab Components для CI/CD
7. **Аудит** - полная история изменений и доступов

## Риски и митигация

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| Сложность миграции существующих данных | Средняя | Высокое | Поэтапная миграция с fallback |
| Проблемы производительности при множественных интеграциях | Низкая | Среднее | Кеширование, connection pooling |
| Ошибки в RBAC логике | Средняя | Высокое | Тщательное тестирование, audit logging |
| Утечка credentials | Низкая | Критическое | Шифрование, Vault интеграция (будущее) |

## Метрики успеха

- Все интеграции управляются через UI без редактирования конфигов
- Время настройки новой интеграции < 5 минут
- Поддержка 10+ одновременных GitLab инстансов
- 100% покрытие RBAC проверками
- Zero downtime миграция с текущей версии
