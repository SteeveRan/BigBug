# Настройка GitHub токена для BigBug

## Проблема с лимитами GitHub API

BigBug использует GitHub API для получения информации о репозиториях и релизах. Без аутентификации GitHub API имеет ограниченные лимиты (обычно 60 запросов в час на IP-адрес). Когда лимит превышается, вы получаете ошибку:

```
Request ... failed with 403: rate limit exceeded
Setting next backoff to ...s
```

## Возможные причины отсутствия релизов

1. **Лимиты GitHub API**: Анонимные запросы ограничены 60 в час, аутентифицированные - 5000 в час
2. **Отсутствие релизов в репозитории**: Репозиторий может не содержать опубликованных релизов
3. **Приватный репозиторий**: Требуется токен с соответствующими правами доступа

## Решение: Настройка GitHub Personal Access Token

### Шаг 1: Создание GitHub Personal Access Token

1. Перейдите на GitHub: https://github.com/settings/tokens
2. Нажмите "Generate new token" → "Fine-grained personal access token" или "Classic personal access token"
3. Для "Classic personal access token":
   - Установите имя токена (например, "BigBug Integration")
   - Выберите права доступа:
     - `public_repo` - для доступа к публичным репозиториям
     - `read:org` - если планируете работать с организациями
     - `repo` - если планируете работать с приватными репозиториями
4. Скопируйте созданный токен (его нельзя будет увидеть снова)

### Шаг 2: Настройка токена в BigBug

#### Вариант 1: Через переменную окружения

Добавьте в ваш файл `.env`:

```
GITHUB_TOKEN=ваш_токен_здесь
```

#### Вариант 2: Через интеграции в интерфейсе

1. Войдите в BigBug под администратором
2. Перейдите в раздел "Settings" → "Integrations"
3. Найдите интеграцию GitHub
4. Добавьте или обновите токен в поле "Token"

### Шаг 3: Перезапустите приложение

После настройки токена перезапустите BigBug, чтобы изменения вступили в силу.

## Проверка работы

После настройки токена:

1. Попробуйте снова добавить или обновить проект из GitHub
2. В логах не должно быть ошибок "rate limit exceeded"
3. Релизы должны начать подтягиваться (если они существуют в репозитории)
4. Обратите внимание, что синхронизация релизов теперь происходит асинхронно в фоновом режиме, поэтому они могут появиться с небольшой задержкой
5. Система теперь использует таймауты для предотвращения блокировки выполнения при медленных или неотвечающих запросах к GitHub API

## Повышенные лимиты

При использовании аутентифицированных запросов лимиты GitHub API значительно выше:
- 5000 запросов в час для аутентифицированных запросов (вместо 60 для анонимных)
