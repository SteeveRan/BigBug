## Диагностика

1. **95% правил — generic-боилплейт** (SOLID, security, error handling, TS best practices с длинными примерами кода). Модель знает это по умолчанию; нулевая проектная ценность, ~17 600 токенов стоимости каждой сессии.
2. **Противоречия в контексте** (агент получает взаимоисключающие инструкции):
   - `effective-comments`/`ai-assistant-guidelines` требуют комментариев и докстрингов ↔ ядро Kilo: «DO NOT ADD ANY COMMENTS unless asked»;
   - `agent-task-process-task-list` требует паузы после каждой подзадачи ↔ автономное итеративное выполнение.
3. **Устаревшие ссылки** в `agent-task-*`: каталог `/tasks/` (в репо — `plans/`), `npx jest` (в репо — Vitest + `make`).
4. **Промпты-фрагменты не на месте**: `check-code-quality`, `small-improvement`, `diff-review` — это ревью-промпты для запуска по требованию, а не правила; грузятся в каждую сессию.
5. **Единственное образцовое правило**: `antd-alert-no-message.md` (1 КБ, короткое, проектно-специфичное) — эталон для будущих правил.
6. `AGENTS.md`: секция «Common Tasks» содержит ~60 строк примеров кода, дублирующих `plans/development/*`; аннотация `.roo/` в дереве репо устарела («Kiro AI rules»).
7. Дублирование: `.roo/rules/` повторяет 26 из 23+3 правил — по ответу пользователя Roo не используется, на стартовый контекст Kilo не влияет.

## Зафиксированные решения пользователя

- Скиллы Matt Pocock (`.agents/skills`) **используются** — не трогаем, их ~2 500 токенов — принятая стоимость.
- PRD/task-list workflow (`agent-task-*`) **не используется** — удаляем.
- Roo (`.roo/`) **не используется** — очистка опциональна, вне стартового контекста.

## План действий

### Задача 1. Удалить 19 правил из `.kilo/rules/` (P0, −17 600 токенов)

Перед удалением: `grep -r "<имя-правила>" AGENTS.md plans/ docs/ .kilo/ .agents/` — убедиться, что нет ссылок.

Удалить:
- Generic-боилплейт (16): `ai-assistant-guidelines`, `dockerfile-best-practices`, `effective-comments`, `fastapi-async-development`, `general-best-practices`, `keep-a-changelog`, `observability-practices`, `optimization-guidelines`, `project-readme`, `react-component-architecture`, `robust-error-handling`, `secure-coding-practices`, `solid`, `typescript-best-practices`, `typescript-node-development`, `typescript-type-safety`
- Неиспользуемый workflow (3): `agent-task-create-prd`, `agent-task-generate-tasks`, `agent-task-process-task-list`

Оставить: `antd-alert-no-message.md` — единственное проектно-специфичное.

### Задача 2. Перевести 3 ревью-промпта в команды (P0, −900 токенов)

Создать `.kilo/command/`:
- `check-code-quality.md` ← тело `rules/check-code-quality.md`
- `small-improvement.md` ← тело `rules/small-improvement.md`
- `diff-review.md` ← тело `rules/diff-review.md`

Формат: frontmatter `description:` (1 строка) + текущий текст промпта. Тела команд грузятся только при вызове `/name`. Исходные файлы из `rules/` удалить.

### Задача 3. Сжать AGENTS.md (P1, −1 200 токенов)

- Секцию «Common Tasks» → «Adding New API Endpoint» и примеры RTK Query заменить ссылками на `plans/development/backend.md` и `plans/development/frontend.md` (там всё есть; AGENTS.md уже инструкктирует читать их по требованию).
- Примеры тестов в «Testing» сократить до списка make-команд.
- Исправить аннотацию `.roo/` в дереве репо (не «Kiro AI rules», а «Legacy Roo rules (не используется)»).
- Структуру, конвенции API/БД, таблицы make-команд — сохранить как есть (высокая ценность).

### Задача 4 (опционально, подтвердить у пользователя). Очистить `.roo/`

Roo не используется: удалить `.roo/rules/` (26 файлов) или весь `.roo/` + `.rooignore`. На стартовый контекст Kilo не влияет — чистка репо от мёртвых файлов.

## Валидация

1. Новая сессия Kilo → убедиться, что из правил загружен только `antd-alert-no-message` (спросить агента или `/status`).
2. Слэш-меню показывает `/check-code-quality`, `/small-improvement`, `/diff-review`; каждый вызов работает.
3. Smoke-тест поведения: фронтенд-задача с `<Alert>` → агент использует `title`, не `message` (правило survived).
4. `git status`/`git diff` — в изменениях только `.kilo/` и `AGENTS.md`; код и тесты не затронуты → `make lint`, `make test-unit-backend` не требуются, но прогнать `make lint` не помешает для чистоты.

## Риски и меры

- **Ссылки на удалённые правила** в docs/plans — закрывается grep-проверкой в задаче 1.
- **Потеря привычного поведения ревью** — промпты сохранены как команды, вызов вручную.
- **Будущие правила** — принцип: правило в `.kilo/rules/` только если оно (а) проектно-специфичное, (б) отличается от знаний модели по умолчанию, (в) короче ~1 КБ. Эталон — `antd-alert-no-message.md`.

## Вне скоупа

- lean-ctx MCP-блок (~900 токенов) — активный инструмент, генерируется сервером.
- Описания скиллов (~2 500 токенов) — используются, приняты.
- Глобальный конфиг `~/.config/kilo/` — вне сендбокса проекта; при желании проверить отдельно на глобальные правила/скиллы.
